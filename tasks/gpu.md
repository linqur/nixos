# dGPU: undervolt, потолок частоты, Dynamic Boost

Статус: закреплено, осталась проверка в играх. Undervolt +350 / 2700 применяет сервис `gpu-uv` (`nixos/gpu-tuning.nix`), Dynamic Boost — `nixos/nvidia.nix`.
Только dGPU, iGPU не трогаем. Проверено на ROG Strix G18 (G815JMR), RTX 5060 Laptop, драйвер 615.71.09, ядро 7.2.10.

## Цель
1. Найти потолок карты: доходит ли до максимума или упирается в мощность / температуру.
2. Понемногу сдвигать кривую V/F (offset), на каждом шаге проверять стабильность и ватты.
3. Решить: оставить частоту (если тепло и шум устраивают) или ещё и снизить её ради потребления.

## Что умеет карта на Linux
- **Напряжение не отдаётся** (у GeForce в NVML нет). Undervolt виден как меньше ватт при той же частоте.
- **Offset кривой — есть**: старый API `GpcClkVfOffset`, диапазон ±1000 МГц. Новый `ClockOffsets` на ноутбуке отдаёт 0…0; `gpu-uv` берёт новый, если он что-то разрешает, иначе старый.
- **Потолок частоты — есть**: `SetGpuLockedClocks` (как `nvidia-smi -lgc`).
- **Лимит мощности — нет**: NVML `SetPowerManagementLimit` → `Not Supported` (на мобильных лимит задаёт прошивка). Диапазон 5–115 Вт только показывается.
- **asus-armoury (`nv_tgp`, `nv_dynamic_boost`, `ppt_*`) — нет**: G815JMR отсутствует в таблице лимитов драйвера, `ENODEV` даже от root (см. [power.md](power.md)).

## Dynamic Boost (nvidia-powerd)
Решение: **включён**, `hardware.nvidia.dynamicBoost.enable` в `nixos/nvidia.nix`. Демон — осознанное исключение: цена несравнимо меньше прироста.
- Без него лимит GPU 50 Вт в любом профиле ASUS. С ним — 100 Вт в простое, 115 Вт под нагрузкой; бюджет делится с CPU.
- dGPU с ним по-прежнему засыпает: `runtime_status` = `suspended` (проверено).
- **Arch** (основная система, gitlab.com/linqur/arch): по репозиторию `nvidia-powerd` не включён (`install.sh` включает только NetworkManager), значит там, вероятно, тоже 50 Вт. Репозиторий от 2025-11 может отставать — проверить на самом Arch: `systemctl is-enabled nvidia-powerd` и `power.limit` в игре.

## Инструменты (`nixos/gpu-tuning.nix`)
- `gpu-uv` (`scripts/gpu-uv.py`): `status`, `sudo set --offset N --max МГц`, `sudo reset`, `log файл.csv`. Колонка `reasons`: `power_cap`, `sw_thermal`, `hw_thermal`, `user_clocks`…; `none` при 100% загрузке — верх кривой. На деле `user_clocks` не появляется даже при частоте ровно на потолке, а `power_cap` стоит и на 42–57 Вт при лимите 115 без среза частоты — срезает только упор `power_w` в `limit_w`.
- Тестовые программы (Superposition, FurMark, gpu_burn, nvtop) из конфига убраны 2026-10-23. Были в `environment.systemPackages` этого модуля; gpu_burn — из отдельного `import pkgs.path` с `cudaSupport = true; cudaCapabilities = [ "12.0" ]` (глобально cudaSupport перевёл бы на CUDA и другие пакеты). FurMark разово: `NIXPKGS_ALLOW_UNFREE=1 nix shell --impure nixpkgs#furmark`.
- Логгер, nvtop, nvidia-smi держат dGPU включённой — закрывать после теста.
- Сброс до перезагрузки: `sudo gpu-uv reset` (в конце падает на лимите мощности — `Not Supported`, offset и потолок к этому моменту уже сброшены); вернуть: `sudo systemctl start gpu-uv`. Другие значения насовсем — `offset` / `maxClock` в модуле.

- Пресет **один и тот же**: Superposition 1440p, шейдеры Extreme, текстуры High, профиль ASUS `performance`, от сети.
- Каждый шаг — свой лог (`gpu-uv log ~/uv-<offset>.csv`), иначе файл перезаписывается.

- `power_cap` мелькает уже на 92–100 Вт: бюджет Dynamic Boost плавает (делится с CPU), на частоту почти не влияет.

- Очки на ватт: +150 43,5 → +300 47,8 → +350 50,6.

- **Clock stretching не подтвердился**: Gflop/s в `gpu_burn` растут с offset — ~12800 до +200, ~13100 на +300 и +350 (+2,3%). Вероятно, gpu_burn упирается в лимит мощности, и undervolt даёт удержать частоту выше. Поэтому gpu_burn на любом offset греет до ~80 °C с вентиляторами на максимуме: ватты те же (упор в лимит), выигрыш уходит в частоту, а не в тепло. Температуру сравнивать по Superposition/играм, не по gpu_burn. Подтверждено (`~/nixos/burn-350.csv`, +350): 114,5 Вт и `power_cap` 100% времени, частота 2692 → ~2635 по мере нагрева 60 → 80 °C, Gflop/s за ней 13356 → 13130. Сравнивать Gflop/s между offset — по итоговому значению (на 80 °C), не по первому.
- **gpu_burn 120 на 80 °C, те же 114,5 Вт** (`~/nixos/burn-200.csv`, `burn-350.csv`): +200 — ~2525 МГц, 12525 Gflop/s; +350 — ~2640 МГц, 13132 Gflop/s (+4,6% частоты, +4,8% Gflop/s). Gflop/s на МГц одинаковые (4,96 / 4,97) → реальная частота = показанной, stretching на +350 нет.
- +400 (`burn-400.csv`, `super-400.csv`): Dynamic Boost в этот раз дал лимит 100 Вт, а не 115 → gpu_burn ~2475 МГц, 12322 Gflop/s, 76 °C; абсолютные цифры не сравнимы, но Gflop/s на МГц 4,98 — stretching нет. Ошибок нет, Xid нет.
- **На +400 ватты в Superposition больше не падают** (76,5 Вт, как на +350), а счёт продолжает ползти вниз (3998 → 3900 → 3868 → 3836). Выигрыш исчерпан: дальше только риск. Падение счёта Superposition — скорее шум или бюджет Dynamic Boost, а не нехватка напряжения.

## Проверка финального offset (+350)
**Решение (2026-10-23): +350 / `--max 2700`.** +400 / 2700 по ваттам в пределах шума (0–2 Вт), счёт стабильно −0,7%, запас до края меньше. Потолок 2700 против эталона: −6% FPS (−1…2 кадра на 30 FPS) за −31% ватт и −8 °C; при нехватке FPS — поднять `--max` до 2900, offset не трогать.

## Закрепление (2026-10-23)
- **D3cold настройки переживают**: dGPU спала ~48 мин (`runtime_status` = `suspended`), после пробуждения offset 350, `gpu_burn -tc` встал на 2685 МГц при 66 Вт (без потолка ушёл бы к ~3000). Держит их, вероятно, `nvidia-powerd` — постоянный клиент драйвера, RM не деинициализируется. Без powerd не проверялось.
- Поэтому сервис `gpu-uv` — oneshot при загрузке, без udev и без повторов при пробуждении dGPU. Плюс повтор после сна системы (`suspend.target` и др.): переживают ли его настройки — не проверено, повтор безвреден.
- Проверить после `switch`: `systemctl status gpu-uv` (в журнале — вывод `status` с offset 350), после сна системы — `gpu-uv status`.
- Осталось: 1–2 ч игры с `gpu-uv log ~/game-350.csv` (смотреть `limit_w`, запас `power_w` до него, частоту при `power_cap`), Xid после; простой, видео, сон/пробуждение.
