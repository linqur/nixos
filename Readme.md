## Архитектура конфигурации NixOS

### Цель

Поддерживать единую переносимую систему NixOS для нескольких сред:

- Виртуальная машина — разработка и предварительное тестирование.
- Внешний SSD — тестирование на реальном оборудовании без замены основной системы.
- Внутренний диск — основная установка.
- Другие компьютеры — повторное использование общей конфигурации с минимальными аппаратными изменениями.

Во всех средах должны сохраняться одинаковые пользователь, пакеты, настройки и пользовательское окружение.

### Принципы организации

1. **Общая конфигурация** — системные пакеты, сервисы, локаль, безопасность и другие настройки, не зависящие от устройства.
2. **Аппаратная конфигурация** — драйверы, графика, энергосбережение, особенности загрузки и оборудование конкретного устройства.
3. **Конфигурация установки** — разметка диска, файловые системы, EFI и параметры, зависящие от целевого носителя.
4. **Home Manager** — пользовательские приложения, shell, Git, редактор, терминал и их настройки; общий для всех устройств.

### Пример структуры

```text
.
├── flake.nix
├── hosts/
│   ├── vm.nix
│   ├── laptop.nix
│   └── desktop.nix
├── disko/
│   ├── vm.nix
│   ├── external-ssd.nix
│   └── internal-ssd.nix
├── nixos/
│   ├── common.nix
│   ├── boot.nix
│   ├── graphics/
│   └── hardware/
└── home/
    ├── default.nix
    └── ...
```

Структура развивается по мере появления реальной необходимости; необязательные файлы заранее не создаются.

### Правила

- Общие настройки определяются в одном месте и переиспользуются всеми конфигурациями.
- Хост подключает только необходимые ему аппаратные модули.
- VM не обязана использовать драйверы физической видеокарты.
- Внешний SSD не считается отдельной аппаратной платформой, если используется на том же устройстве: отдельно задаются параметры диска и установки.
- Для разных устройств допускаются отдельные аппаратные конфигурации при сохранении общего системного и пользовательского слоёв.
- Аппаратные идентификаторы и пути к дискам не размещаются в общих модулях.
- Перед форматированием диска проверяется целевое устройство.
- VM используется для тестирования общей конфигурации; реальное оборудование проверяется на физическом устройстве.

### Этапы тестирования

1. Разработка и базовая проверка в VM.
2. Проверка оборудования и графики на внешнем SSD.
3. Установка на внутренний диск.
4. Повторное использование общей конфигурации на других устройствах.
