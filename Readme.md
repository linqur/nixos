# NixOS Flake — Portable System Configuration

Единая конфигурация NixOS на базе Flakes для нескольких устройств: виртуальной машины, ноутбуков и будущих компьютеров.

Главная цель проекта — поддерживать общую систему и пользовательское окружение в одном репозитории, изолируя различия оборудования и разметки дисков в отдельных конфигурациях.

## Цели проекта

- **Единая конфигурация:** общие системные пакеты, сервисы, настройки и пользовательское окружение.
- **Несколько устройств:** возможность использовать одну конфигурацию на разных компьютерах.
- **Профили устройств:** явное описание типа окружения и оборудования каждого хоста.
- **Модульность:** разделение общих настроек, оборудования, хостов и Home Manager.
- **Портативность:** возможность загрузить систему с внешнего SSD на совместимом компьютере.
- **Безопасное тестирование:** проверка конфигурации в VM и на внешнем SSD до переноса на внутренний диск.
- **Воспроизводимость:** фиксация версий зависимостей через `flake.lock`.

## Поддерживаемые сценарии

| Хост | Назначение | Графика |
|---|---|---|
| `vm` | Разработка и первоначальное тестирование | Виртуальный GPU |
| `home-rog` | Основной ноутбук | Intel iGPU + NVIDIA RTX 5060 |
| `laptop-old` | Старый ноутбук | Устаревшая NVIDIA или другая графика |

Названия хостов условные: фактические имена должны совпадать с конфигурациями в репозитории.

В будущем можно добавлять новые устройства, не изменяя общую конфигурацию без необходимости.

## Архитектура

### 1. `flake.nix` — точка входа

Flake отвечает за:

- подключение зависимостей (`inputs`);
- объявление систем NixOS;
- создание `nixosConfigurations`;
- выбор профиля каждого хоста;
- передачу общих аргументов модулям через `specialArgs`;
- подключение общих и специфичных конфигураций.

Здесь определяется, **какие системы собираются**, но по возможности не размещаются подробные настройки оборудования.

### 2. `lib/enums.nix` — единые значения

Централизованное описание допустимых значений, используемых в профилях и модулях.

Например:

```nix
{
  gpu = {
    intel = "intel";
    nvidia_intel = "nvidia_intel";
    nvidia_legacy = "nvidia_legacy";
    virtual = "virtual";
  };

  environment = {
    laptop = "laptop";
    desktop = "desktop";
    vm = "vm";
  };
}
```

Использование общих значений уменьшает количество опечаток и исключает повторение произвольных строк в разных файлах.

Важно: такой файл сам по себе не обеспечивает строгую проверку типов. Если потребуется проверять допустимые значения средствами системы модулей NixOS, можно позднее определить собственные параметры через `options` и `types.enum`.

### 3. `hosts/` — конфигурации конкретных машин

Каждый хост содержит два основных файла.

**`profile.nix`**

Описывает характеристики устройства: тип окружения, графическую подсистему и другие признаки, влияющие на выбор модулей.

Пример профиля основного ноутбука:

```nix
{ enums }:
{
  environment = enums.environment.laptop;
  gpu = enums.gpu.nvidia_intel;
}
```

Пример профиля виртуальной машины:

```nix
{ enums }:
{
  environment = enums.environment.vm;
  gpu = enums.gpu.virtual;
}
```

Это обычная функция Nix, возвращающая набор атрибутов. Она не является NixOS-модулем.

Профиль задаётся явно в конфигурации хоста. Он не определяет видеокарту путём автоматического обнаружения: его задача — сообщить конфигурации, для какого окружения она предназначена.

**`configuration.nix`**

Подключает необходимые общие и аппаратно-зависимые модули для конкретного хоста.

Например:

- общую системную конфигурацию;
- профиль загрузки;
- настройки графики;
- параметры виртуальной машины;
- настройки энергопотребления ноутбука;
- конфигурацию Home Manager.

Общие настройки не следует копировать между хостами, если их можно вынести в повторно используемые модули.

### 4. `hardware/` — аппаратно-зависимые настройки

Здесь располагаются модули, зависящие от реального или виртуального оборудования.

Примеры:

- Intel iGPU;
- современная NVIDIA;
- старая NVIDIA;
- гибридная графика Intel + NVIDIA;
- виртуальная графика QEMU/KVM;
- особенности загрузки и ранней инициализации графики;
- энергопотребление и функции ноутбуков.

Аппаратные модули подключаются из конфигурации соответствующего хоста либо выбираются на основании его профиля.

Не каждое отличие требует отдельного файла: связанные настройки одной аппаратной функции можно держать вместе, если так проще поддерживать их согласованность.
